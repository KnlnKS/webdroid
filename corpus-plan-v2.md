# Compatibility corpus handoff

Status: 2026-09-25. This is the working plan for the 15 open-source APKs in [docs/compatibility-corpus.md](docs/compatibility-corpus.md), which records their source links, exact filenames, SHA-256 hashes, initial missing calls and longer investigation notes. The APKs are ignored by Git and live in the main checkout's `apks/` directory. All 15 have drawn an initial frame in the repeat launch scan, but **none has been established as fully usable**. Missing-call telemetry covers only executed paths, and the initial launch results in that document are historical, not the current failure list.

## Findings that matter for the next pass

- The corpus has already exposed shared correctness bugs, not just absent methods: stale `RandomAccessFile` snapshots across parallel writes; a native file handle with a shorter view than the VFS's logical length; a freed joinable pthread handle reused before `pthread_join`; source annotation arrays without Java array types; and external-storage files not restored before app startup. Their mechanisms and evidence are in [docs/implementation-history.md](docs/implementation-history.md).
- Organic Maps' second file bug made a byte-perfect Monaco download fail the app's BLAKE3 check. The latest fix always updates an open VFS file's data view when `vfs.write` publishes bytes. A focused test covers a longer view of the same backing buffer. `Collections.rotate(List, int)` now writes through the list iterator, including live sublists. Opening a place found that missing call.
- Starting Organic Maps navigation found `Context.createAttributionContext` and `MediaPlayer.setAudioAttributes`. Attribution contexts retain the base context and expose the requested tag/source. MediaPlayer now reads file-descriptor byte ranges, releases blob URLs, and calls its prepared listener on preparation rather than listener registration. Android's [Context](https://developer.android.com/reference/android/content/Context) and [MediaPlayer](https://developer.android.com/reference/android/media/MediaPlayer) contracts guided these changes. The final route snapshot had no missing call, but voice playback requires a separate real-app check.
- `androidx.window` sidecar and extension provider classes are optional OEM probes. Do not fabricate them just to clear telemetry. Treat other empty missing lists as observed-path evidence only; check child processes, `run.json`, frames, interaction and persisted state.
- OpenTracks exposed standard Stream, SQLiteQueryBuilder, ContentValues, ContentResolver observer, PendingIntent activity-stack, java.time, ViewGroup layout-mode and LogPrinter gaps. A missing method during RecyclerView measure left its state at step 2, producing repeated `assertLayoutStep` errors on later frames; the clean detail and recording replays had zero layout errors after filling those methods. The current content observer implementation covers a single process realm only; cross-process notifications still need a broker path. DEX confirmed the Stop control uses `setOnLongClickListener`; ordinary clicks only show the app's “hold to stop” toast.
- OpenTracks' Share previously launched its own ImportActivity because `Intent.createChooser` returned the wrapped `SEND_MULTIPLE` intent. The chooser now routes to the host share path; opening its content URI exercised `Stream.toArray(IntFunction)`, `ContentProvider.openPipeHelper`, ZIP output and ISO offset formatting. The provider helper currently buffers output before returning its read descriptor. Chrome's native share API was denied in this DevTools session, so Save file supplied the verified archive. Native share delivery on another browser remains unverified.
- OpenTracks binds its recording service with flags `0` before explicitly starting it. Webdroid previously discarded that binding, leaving Record on the home screen; the starting commit reproduced the stall. Non-auto-creating bindings now wait for the service to start. With a granted browser geolocation, the first fix exposed `Instant.plus(TemporalAmount)` in track-point creation. That method now delegates to the amount's `addTo`, and Duration supplies the corresponding operation. A controlled GPS replay recorded, stopped, reloaded and exported two position fixes with no observed missing API or uncaught error.
- OpenTracks' Import all exposed a resource-backed explicit component in Intent XML, SAXParser's InputStream overload, ISO_DATE_TIME `parseBest`, `ContentResolver.bulkInsert` and long-stream operations. The completed KMZ replay exercised each; the importer worker succeeded and Open Track displayed the imported statistics. Its Show on map action reported that OSMDashboard was not installed.
- AntennaPod's feed path exposed missing SQL string escaping, a copied rather than live `ArrayAdapter` list, a Reader shortcut that bypassed an app Reader's virtual `read`, StringReader mark/reset, CharBuffer backing-array access and a SAXParser overload. Its playback path then exercised PendingIntent type queries, foreground-service pending intents, media session/controller methods, KeyEvent parceling, notification extras, shared memory and a service foreground overload. The app's OkHttp selected JVM Conscrypt because `java.vm.name` was `webdroid`; reporting Android's `Dalvik` selected its Android platform path and made Glide artwork load. MP3 was absent from the advertised WebCodecs formats; adding it yielded decoded audio buffers and an advancing player. The metadata retriever only parsed MP4, so the completed MP3 download initially logged an invalid media source. MPEG frame/Xing duration parsing removed that error. Pause/resume and first-episode position behavior remain inconsistent.
- AntennaPod's downloaded episode exposed a Handler cancellation bug. RxJava's worker calls `removeCallbacksAndMessages(workerToken)`, but Webdroid canceled all messages on that Handler, including a separate direct callback carrying the loaded FeedMedia. The callback was visibly removed from the queue despite having a different token. Token-filtered cancellation now preserves it, and a reload replay showed the player and responsive Play/Pause controls.
- The second AntennaPod stream's frozen display came from its position observer skipping events when ExoPlayer's duration was unknown. The BBC MP3 has `Content-Length`, but Webdroid's proxy discarded it. Identity responses now carry an internal length header that `HttpURLConnection` exposes as `Content-Length`; an uncached replay showed a known duration and advancing UI time. Chrome had cached older proxy responses for that signed URL, so a forced uncached replay was necessary to check the fix. A swipe also reached `OverScroller.fling` with overfling ranges; its bounded motion now springs back to the valid scroll range.
- Fossify File Manager's selection listener called the missing `Activity.startActionMode(Callback)` and then `ActionMode.setCustomView`. Activity now owns the mode lifecycle and contextual bar; the bar hosts the app's custom view and dispatches menu actions through `onActionItemClicked`. Rename reached the missing NIO `Files.createTempFile(Path, String, String, FileAttribute[])`; the VFS now creates a unique file in the requested directory. A clean replay renamed `notes.txt` to `renamed.txt` without a missing API. A normal sustained press at y=235 selected the row; the previous y=170 probes hit the toolbar layered over its top edge. An empty text file still produces Glide media-thumbnail probe failures, which are expected image-decode fallbacks rather than a failed rename.
- File Manager's Copy to picker initially logged a fast scroller `lateinit recyclerView` exception. Its DEX posts a runnable during `onFinishInflate`, before the view is attached. `View.post` now queues callbacks on unattached views until attachment, as Android does. A clean picker replay showed the destination list with no exception or missing API; an earlier copy placed `renamed.txt` in `/sdcard`.
- Aegis backup settings cloned encrypted vault credentials through Java serialization. The native `SecretKeySpec` lacked its serialized `algorithm` and `key` fields and stored the Java byte array as a `Uint8Array`, which the object stream identified as a boolean array. Its fields and signed byte representation now match Java. The clone then reached `LinkedHashMap`; `HashMap` now writes its load factor, threshold, capacity and entries, while `LinkedHashMap` writes its access-order field. A live replay opened backup settings, selected a browser-granted test folder and produced encrypted automatic and manual backup files without an uncaught error. Importing one of those files into a separate empty browser context restored the entry and code, which survived a further reload.
- Aegis Scan image wraps `ACTION_PICK` for `image/*` and MediaStore's image collection in an `ACTION_CHOOSER`. Webdroid had no handler for that pick action. The platform picker now returns a readable document URI for media MIME types. Aegis decoded a local OTP QR PNG through its own decoder, displayed its prefilled entry form, and retained the saved entry after reload. Camera scanning is separate and remains unverified.
- Fossify Calendar's repetition picker constructed `android.widget.RadioGroup.LayoutParams`, which was missing. The Android nested class and RadioGroup's layout-parameter generation now use a `LinearLayout.LayoutParams` subtype with wrap-content defaults. A weekly series appeared on September 25 and October 2; changing only October 2 retained the original series title on October 9. The changed occurrence survived reload without a runtime missing API or uncaught error.
- Mihon's archive reader called `Os.mmap` on a parcel file descriptor; the missing call left Local source with zero chapters. Java mapping now uses the native guest arena and shares writable-map sync with libc. `Os.getenv` and Java/libc environment reads share one process environment; that second missing call otherwise stopped reader startup. The two-page local CBZ replay exercised both APIs and native archive decode.
- Mihon's Restore backup used `Intent.createChooser(GET_CONTENT)`. The chooser previously accepted only SEND actions even though Webdroid already had a GET_CONTENT file picker. It now dispatches supported system activities through their existing handlers. Chrome selected the saved backup. A separate isolated context showed an empty library before restore and one title with Chapter 1 afterward; the worker reported success. Chrome restarted during the reload check, so persistence in that ephemeral context was not verified.
- Do not implement ad or ad SDK APIs as part of this corpus. Use framework, DEX and native evidence for general behavior; avoid app-specific substitutes.
