# Wasm backend research

Research only; nothing here is imported by `src/`. The plan is `docs/wasm-backend-plan.md`.

Setup: `cd research/wasm && bun install` (binaryen, wabt, playwright from the repo root). Timing scripts
(`micro/*.mjs`) need Chrome and report indicative single runs.

- `probe.mjs <chrome|chromium|webkit> [--flags=a,b] [--nolimits]` feature and limit matrix (see `platform-status.md`)
- `probe-tiering.mjs hints|cache [chrome|chromium|node]` compilation-hint and code-cache checks; the instrumentation is V8's trace output read with `DEBUG=pw:browser`

- `micro/` microbenchmarks; `gc/` Zig mark-sweep (`zig build-exe gc.zig -target wasm32-freestanding -O ReleaseFast -fno-entry -rdynamic --import-memory -femit-bin=gc.wasm`)
- `dexstats/`, `survey/` static analyses (run from their directory; `survey/out` is regenerated by `ast-survey.ts`)
- `j2w/` incomplete DEX to Wasm-GC prototype, compiled lazily at run time: `bun build.ts <dex|jar>... --entry 'W.fib(I)I'` runs entries and prints the compile statistics; harnesses `diff.ts`, `libdiff.ts`, `jbench.ts`, `lazytest.ts` (needs javac, d8, java on PATH), `lazybench.ts`, `floatbench.ts`; `g1.ts` times the jbench workloads (and `j2w/java/G1.java`'s) as Wasm against the JS tier in node and headless Chrome (see plan 4.6), `watdump.ts <workload> <method>` prints the generated code
- `*.md` reports from the analyses
